# Data model (draft)

Postgres on Supabase. This is a draft. The source of truth becomes `supabase/migrations/`, so update this file in the same change as any migration.

## Conventions
- `uuid` primary keys. User-written tables use **client-generated UUID v7**.
- User-written tables have `created_at`, `updated_at` (server-stamped by trigger) and `deleted_at` (soft delete).
- All timestamps are `timestamptz` (UTC).
- Tables are `snake_case` and plural. **RLS on every table.** "Owner" means `user_id = auth.uid()`.

## Stage 1

| Table | Columns | RLS |
|---|---|---|
| `profiles` | `id` (= auth.users.id, `on delete cascade`), `username` unique (`[a-z0-9_]{3,20}`), `display_name` (≤ 50), `avatar_url` (https), `locale` (default `en`), `time_zone` (IANA, validated by `is_time_zone()`, default `UTC`), `country`, `visibility` (`public`/`private`, default public), `theme` (`system`/`light`/`dark`), `email_recaps` (default true), `created_at`, `updated_at` | Created only by the `on_auth_user_created` trigger (`handle_new_user()`: username from the Google name or email, locale/time zone from sign-up metadata, [ADR 0020](../decisions/0020-auth-passwordless-ssr.md)). Owner reads the row and updates the settings columns (column grants; not `id` or the timestamps). No client insert/delete: account deletion deletes the auth user and the profile cascades. Public profile pages read a safe subset through `public_profile(username)` (security definer: id, username, display name, photo, join date; a private profile returns only its username and `is_private`). Usernames and display names pass the `profiles_check_names` trigger (reserved route/role names, the brand, a short slur list; SQLSTATE 23514 with the column in the hint), [ADR 0027](../decisions/0027-public-profiles-preferences-reports.md). |
| `entries` | `id` (UUID v7), `user_id` (→ `profiles(id)` `on delete cascade`, default `auth.uid()`), `title_id` (→ `titles`), `status` (`want`/`watching`/`finished`), `finished_at` (set exactly when `finished`), `rating` (0.5–5 in half steps), `review` (1–280 chars), `created_at`, `updated_at`, `deleted_at` | Owner reads all own rows (incl. soft-deleted) and inserts/updates; others (incl. anon) read live rows if the owner is public (`private.is_public_profile`). No client DELETE; clients update only `status`, `finished_at`, `rating`, `review`, `deleted_at`. Unique (`user_id`, `title_id`) where not deleted. |
| `episode_logs` | `id` (UUID v7), `user_id` (→ `profiles(id)` cascade), `title_id`, `season` (0 = specials), `episode`, `runtime_min` (copied at log time), `watched_at` (default now), `created_at`, `updated_at`, `deleted_at` | Same as entries; clients update only `runtime_min`, `watched_at`, `deleted_at`. Unique (`user_id`, `title_id`, `season`, `episode`) where not deleted. |
| `title_episodes` | PK (`title_id` → `titles` cascade, `season`, `episode`), `name`, `runtime_min`, `air_date`, `fetched_at`, `created_at`, `updated_at` | Read all. Server writes (TMDB cache via `ensureEpisodes` in `src/data/episodes.ts`: numbered seasons only, refreshed after 1 day for running series, 30 days for ended ones; `titles.raw->>status` says which). |
| `cards` | `id` (UUID v7), `user_id` (→ `profiles(id)` cascade), `entry_id` / `episode_log_id` / neither (composite FKs with `user_id`, so only the owner's rows), `kind` (`finish` needs an entry, `progress`, `sticker`, `weekly_recap` and `stats` have no source; `stats` = Share stats from the stats page, [ADR 0026](../decisions/0026-stats-page.md)), `template_id` (registry id, e.g. `boldStats`), `size` (`story`/`feed`), `params jsonb` (object, ≤ 16 KB), `image_path` (must be `<user_id>/<id>.png`), `shared_at`, `created_at`, `updated_at`, `deleted_at` | Owner reads all own rows and inserts/updates; no client DELETE. Anyone can list the live shared cards of a public profile (the gallery). A card link works even on a private profile through `shared_card(id)` (security definer, needs the id), which also returns the owner's current username when the profile is public ([ADR 0027](../decisions/0027-public-profiles-preferences-reports.md)). Written through `POST /api/cards` (`src/data/cards.ts`): `params` is the validated `CardData` snapshot plus `username`, which the server sets from the profile (null when hidden). |
| `reports` | `id` (UUID v7, made by the server), `reporter_id` (→ `profiles`, `on delete set null`), `target_kind` (`profile`/`card`), `target_id` (profile or card id), `reason` (`spam`/`harassment`/`hate`/`sexual`/`impersonation`/`other`), `note` (≤ 500), `created_at`, `updated_at`, `resolved_at` | No client access at all (RLS on, no policies, all privileges revoked). Written by `POST /api/reports` with the service role (honeypot, rate limit; public targets only). Read by the operator with an admin query. |
| `weekly_recaps` | `id` (UUID v7), `user_id` (→ `profiles(id)` cascade), `week_start` (the local Monday), `stats jsonb` (the `CardRecap` snapshot, ≤ 16 KB), `card_id` (→ `cards`, set null), `notified_at`, `pushed_at`, `created_at`. Unique (`user_id`, `week_start`) | Owner reads. Server writes (service role; no client insert/update/delete). `weekly_recap_candidates(now, limit)`, `weekly_recaps_to_notify(limit)` and `weekly_recaps_to_push(limit)` are service-role only ([ADR 0025](../decisions/0025-weekly-recaps.md), [ADR 0028](../decisions/0028-home-pwa-web-push.md)). |
| `push_subscriptions` | `id` (UUID v7, made by the server), `user_id` (→ `profiles(id)` cascade), `endpoint` unique (≤ 1024, a known push service), `p256dh`, `auth` (base64url), `created_at`, `updated_at` | No client access (RLS on, all privileges revoked). Written by `POST`/`DELETE /api/push` and sign-out with the service role after verifying the user. A device token, not user content: hard-deleted on "off", sign-out, a 404/410 from the push service, and with the account ([ADR 0028](../decisions/0028-home-pwa-web-push.md)). |

Implemented so far: `profiles` in `supabase/migrations/20260927100000_stage1_profiles.sql` (tested in `supabase/tests/database/stage1_auth.test.sql`), and `entries`, `episode_logs`, `title_episodes`, `cards` in `20260927110000_stage1_collection.sql` (tested in `stage1_collection.test.sql`; the rules are explained in [ADR 0021](../decisions/0021-collection-tables-rules-in-the-database.md)). Storage: the public `cards` bucket (`20260927120000_stage1_card_images.sql`, tested in `stage1_card_images.test.sql`) holds shared card PNGs at `<user_id>/<card id>.png`, PNG only, ≤ 5 MB. Clients have no write policies; uploads use a signed URL the server creates after saving the card, and account deletion removes the user's folder ([ADR 0024](../decisions/0024-card-saving-and-share-links.md)). Weekly recaps: `weekly_recaps`, `profiles.email_recaps` and the hourly `weekly-recaps` pg_cron job (pg_net → the app; URL and secret in Vault) are in `20260927130000_stage1_weekly_recaps.sql` (tested in `stage1_weekly_recaps.test.sql`). Profile & privacy: the name blocklist trigger, `public_profile()`, `shared_card()`, the stricter shared-card policy and `reports` are in `20260927150000_stage1_profile_privacy.sql` (tested in `stage1_profile_privacy.test.sql`). Web push: `push_subscriptions`, `weekly_recaps.pushed_at` and `weekly_recaps_to_push()` are in `20260927160000_stage1_home_push.sql` (tested in `stage1_home_push.test.sql`). Ids for user rows come from `uuidv7()` in `src/core/ids.ts`; the database rejects other UUID versions. **Every user table references `profiles(id)` with `on delete cascade`**, so deleting an account (`DELETE /api/account`) removes all of it.

# Internationalization & global readiness

Decision: [ADR 0007](../decisions/0007-english-first-global.md). Mystonie is a **global product**. English is the default and the brand voice. Thai is the first optional locale. Nothing in the core product should signal a particular home country.

## Languages
- Library: **next-intl** with locale-prefixed routes. `en` is the default with no prefix (`/stats`), other locales are prefixed (`/th/stats`).
- Messages: `messages/en.json` (source of truth, written first) and `messages/th.json`. Missing keys fall back to English.
- **No hard-coded UI strings** in components. Enforced by `react/jsx-no-literals` in `eslint.config.mjs` (visible JSX text must come from `t(...)`; props and separators are allowed; `src/components/ui` is exempt).
- Locale resolution: **the URL decides** (no prefix = `en`). There is no automatic redirect from `Accept-Language` and no locale cookie, so every visitor lands in English and switches deliberately (owner decision 2026-09-26). From stage 1, a signed-in user's `profiles.locale` redirects them to their chosen locale: the proxy mirrors the saved language (and theme) into the `mystonie_prefs` cookie while they're signed in, and both language menus save the choice to the profile first ([ADR 0027](../decisions/0027-public-profiles-preferences-reports.md)). At sign-up, `profiles.locale` is the locale of the page they signed up on: a language they picked in the URL, never a detected one ([ADR 0020](../decisions/0020-auth-passwordless-ssr.md)). A language menu is always available in Settings and the footer.
- Emails (auth, recaps) are localized with the same keys (`Emails.*`). Supabase Auth hands its emails to our Send Email Hook route, which picks the locale from the page the person signed in on ([ADR 0020](../decisions/0020-auth-passwordless-ssr.md)).
- Title names come from TMDB in the user's language when available (`language` param), falling back to the original title.

### Implementation (stage 0)
| Piece | Where |
|---|---|
| Locales, default, prefix mode (`as-needed`) | `src/i18n/routing.ts` |
| Rewrite to `/[locale]` from the URL prefix only (`localeDetection: false`, `localeCookie: false` in `routing.ts`) | `src/proxy.ts` (Next 16 "proxy", formerly middleware). Skips `/api`, `/_next`, the generated `/apple-icon` and `/opengraph-image` routes, and files with an extension. Also sends `hreflang` alternate `Link` headers. |
| Messages + per-key English fallback | `src/i18n/request.ts` deep-merges `th.json` onto `en.json` (`merge-messages.ts`) |
| Type-safe keys and locales | `src/global.d.ts` (`AppConfig`) |
| Navigation | Import `Link`, `useRouter`, `usePathname`, `redirect` from `@/i18n/navigation`, never from `next/link` / `next/navigation` (except `notFound`) |
| Language menu | `src/components/locale-switcher.tsx`: native `<select>`, each language shown in its own script via `Intl.DisplayNames`. Currently in the footer of `[locale]/layout.tsx`. |
| 404 | `[locale]/not-found.tsx`, reached for unknown paths through `[locale]/[...rest]/page.tsx` |

Adding a language: add the code to `routing.ts` and create `messages/<code>.json` (it may be partial). A test fails if a locale file has keys that `en.json` doesn't.

Server components that render statically call `setRequestLocale(locale)` before using translations.

## Formatting
- Dates, numbers and durations use `Intl` (`DateTimeFormat`, `NumberFormat`, `RelativeTimeFormat`) with the user's locale. Runtime formatting (`2h 36m`, `156 min`) lives in `src/core/format/runtime.ts` with locale-aware unit labels (`Intl.NumberFormat` units + `Intl.ListFormat`).
- Week start follows the locale (Monday or Sunday) for heatmaps and "this week" stats (`weekStartFor` in `src/core/stats/period.ts`; Monday when the runtime has no week data). Weekly recaps always cover Monday–Sunday, since they arrive on Monday ([ADR 0025](../decisions/0025-weekly-recaps.md)).

## Time zones
- Store every timestamp as `timestamptz` (UTC).
- `profiles.time_zone` (IANA) is detected at sign-up and editable.
- "Today", "this week" and recap periods are computed in the user's time zone (`periodRange` / `startOfLocalDay` in `src/core/stats/period.ts`, plain `Intl`, no date library). Future anti-abuse daily limits (quiz, wheel) use **server UTC**.

## Cards & fonts
- Cards may contain any script (user reviews in Thai, Korean, Japanese, …). The card renderer runs in the browser for correct text shaping ([ADR 0008](../decisions/0008-client-side-card-rendering.md)).
- The font stack is the brand Latin font followed by Noto Sans Thai, Noto Sans KR, Noto Sans JP (subset / loaded on demand).

## Region-dependent data
- **Where to watch:** by profile country (TMDB watch providers).
- **Pricing:** USD via Stripe. Local currency display is Stripe's job.

## Legal (global)
- Privacy Policy + Terms from stage 0.
- Analytics: PostHog in cookieless mode (no consent banner). If cookies or session replay are ever enabled, add a consent banner for EU/UK visitors.
- Users can export and delete their data (GDPR, UK GDPR, CCPA, PDPA).

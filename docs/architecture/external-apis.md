# External APIs

**Rule:** keys live on the server. The browser only calls our route handlers. Responses are normalized in `src/core/catalog` and cached in Postgres. Each provider sits behind a small interface so it can be swapped.

## Our catalog routes (stage 0)
Implemented in `src/app/api/`, TMDB client in `src/data/tmdb.ts`, normalizers in `src/core/catalog/tmdb.ts` (fixture tests). Caching, limits and language: [ADR 0012](../decisions/0012-catalog-api-caching-and-limits.md).

| Route | Returns | Rate limit (per IP hash) |
|---|---|---|
| `GET /api/search?q=` (2–100 chars) `&type=all\|screen\|book\|manga\|game` | `{ results: SearchResult[] }`. No type = `screen`: movies + series, top 20 by TMDB popularity (the card maker). `book` Google Books, `manga` AniList, `game` RAWG. `all` (the collection's sheet) merges them by name match, catalogs taking turns, each catalog's first pick near the top (`mergeSearch`), leaving out a catalog that fails; RAWG only from 3 characters, its 8 best-known games | 60/min |
| `GET /api/trending` | `{ results: SearchResult[] }`, `/trending/all/week` | 30/min |
| `GET /api/titles/tmdb/{movie\|series}/{id}` | `{ title: Title }`, cached in `titles` for 7 days | 30/min |
| `POST /api/episodes` (signed in) | Logs episodes (`watchedAt?`: the device time of a log that waited offline); caches the series' seasons (`/tv/{id}/season/{n}`, all numbered seasons) in `title_episodes` first when missing or old | 120/min |
| `POST /api/entries` (signed in) | Quick add (any kind, `editedAt?`); caches the title from its catalog, and for a series its episodes after responding. `{ entry, superseded? }`: `superseded` when the entry was changed after `editedAt` and stays as it is. `PATCH /api/entries/[id]` (status, notes or removal, `editedAt?`) answers the same way | 60/min |
| `POST /api/reading` (signed in) | Logs a reading checkpoint (`{ id, kind, externalId, unit, position, readAt? }`); caches the book or manga first; `PATCH /api/reading/[id]` un-logs | 120/min |
| `GET /api/covers/[volumeId]` (`?size=large`) | A Google Books cover from our origin (300 / 575 px), CDN-cached a month; fetches only Google's cover endpoint | – |
| `POST /api/import/match` (signed in) | `{ items: ItemQuery[] }` (≤ 20) → `{ matches: FilmMatch[], have: { "kind:externalId": status } }`: each imported title found in its catalog, 4 at a time: films on TMDB `/search/movie` (by year, then without; ADR 0033), shows by TheTVDB id (`/find`) then `/search/tv`, books on Google Books (`isbn:`, then `intitle:` + `inauthor:`), MyAnimeList entries through AniList `idMal_in` (manga directly, anime by name on TMDB), Mystonie's CSV by catalog id from the cache ([ADR 0041](../decisions/0041-import-export.md)) | 120/min |
| `POST /api/import/commit` (signed in) | `{ rows: ImportRow[] (≤ 25, ≤ 5 series with episodes, ≤ 3,000 logs), done? }` → `{ results }`: saves confirmed titles idempotently with their episodes and reading logs, caching each title (and a series' episodes) first; `done: true` ends the import (milestones, badges, challenges recorded silently) | 120/min |
| `GET /api/account/export/csv` (signed in) | → a ZIP of `collection.csv`, `episodes.csv`, `reading.csv` (the CSV export, which imports back) | – |
| `PUT /api/warnings/topics` (signed in) | `{ topicIds }` (≤ 300 DTDD topic ids) replaces the user's avoid-topics | 60/min |
| `POST /api/warnings/badges` (signed in) | `{ titles: [{ kind, externalId }] }` (≤ 40, any kind) → `{ badges: { "movie:245891": [{ id: 153, name: "a dog dies" }] } }`: the user's avoid-topics each title has a Yes for, from DTDD's cached votes and our own confirmed warnings and quiz answers (stage 3; those have no `name`, the app names them); never calls DTDD | 60/min |
| `GET /api/warnings/{movie\|series}/{id}` (signed in) | `{ status: "matched" \| "unmatched", survived }`: looks the title up on DTDD when not cached, for the finish celebration's Survived offer ([ADR 0035](../decisions/0035-content-warnings-cache-and-survived.md)) | 30/min |
| `POST /api/scene-warnings` (signed in) | `{ id, titleId, topic, season?, episode?, startSec?, endSec?, unit?, position? }` → 201 `{ warning }`; 403 `not_seen` (not watching or finished), 409 `duplicate`, 429 `daily_limit` (30 a day) or rate limited, 400 `invalid` (the database checks topic and place against the kind) ([ADR 0043](../decisions/0043-scene-warnings-and-quiz.md)) | 30/10 min |
| `PUT /api/scene-warnings/[id]` (signed in) | `{ vote: 1 \| -1 \| 0 }` (saw it, not there, take back) → `{ status, confirms, disputes, myVote }`; 404 when the user may not vote on it (their own, gone, not watched). `DELETE` withdraws the user's own waiting warning (404 once confirmed) | 120/10 min |
| `GET /api/quiz?title=` (signed in) | The next warnings-quiz question: `{ status: "question", id, kind, topic, title, where, answers }`, or `paused` (`until`), `no_finishes`, `done`. `POST /api/quiz` `{ id, choice: "yes" \| "no" \| "unsure" }` → `counted` / `not_counted` (with the question's or warning's state), `too_fast`, `paused`, `answered`, `gone`. The database serves and times both | 120/min |
| `POST /api/milestones` (signed in) | `{ milestones: CardData[] }`: the milestones just crossed (each once), as Milestone card inputs; called after a finish or a log is saved ([ADR 0031](../decisions/0031-milestones-monthly-recap-year-in-review.md)) | 60/min |
| `POST /api/billing/checkout` (signed in) | `{ plan }` (monthly or yearly) → `{ url }` of a Stripe Checkout Session (409 `already_pro`). Also `POST /api/billing/portal` → `{ url }` of the Customer Portal (404 without a customer), `GET /api/billing/status` → `{ available, pro, renewsAt, cancelAtPeriodEnd }`, and `POST /api/billing/webhook` (Stripe-signed, 400 `invalid_signature`). All answer 503 while Pro is off ([ADR 0034](../decisions/0034-pro-subscription.md)) | 10/min (checkout and portal) |

The collection writes (entries, episodes, reading, and their `PATCH` routes) are also what the offline outbox replays ([offline sync](offline-sync.md)). They accept an optional `X-Mystonie-User` header: when it isn't the signed-in user, they answer `409 other_account` and save nothing, so a change made in one account never lands in another.

Errors are JSON `{ error }`: `400 invalid_query`, `404 not_found`, `429 rate_limited` (with `Retry-After`), `502 catalog_error`, `503 catalog_unavailable` (no `TMDB_API_TOKEN`). Attribution (logo + notice) is in the site footer (`src/components/tmdb-attribution.tsx`, logo in `public/attribution/`).

## Normalized search result (`src/core/catalog`)
```ts
type SearchResult = {
  source: 'tmdb' | 'google_books' | 'anilist' | 'rawg';
  externalId: string;
  kind: 'movie' | 'series' | 'book' | 'manga' | 'game';
  name: string;
  originalName?: string;
  year?: number;
  originalLanguage?: string;
  imageUrl?: string; // small poster (TMDB w342, AniList medium, our book cover proxy, RAWG art 420 px wide)
  creator?: string; // a book's first author
  platforms?: string[]; // a game's platform families ("PC", "PlayStation", …)
};
```
The UI composes any subtitle ("Series · 2016") from `kind` + `year` through next-intl. A picked title is a `Title` (same file, mirrors the `titles` table).
